# 동시성 이슈와 제어 방식에 대한 보고서

## 동시성 이슈 정의

**동시성 이슈**는 **공유자원**에 접근하는 임계지점(critical section)에서 다수의 스레드가 공유자원에 접근할 때 경쟁상태(race condition)로 인해 결과가 달라지는 문제입니다.

---

## 자바 소스코드에서 동시성을 제어하는 방법

자바에서 동시성을 제어하는 주요 방식은 다음과 같습니다:

1.  **`synchronized` 키워드 사용**
2.  **`ReentrantLock`**
3.  **`Semaphore`**
4.  **`ReadWriteLock`**

### 동시성 제어 방식 비교

| 제어 방식 | 동시성 수준 | Lock 획득/해제 오버헤드 | 특징 및 장점 |
| :--- | :--- | :--- | :--- |
| `synchronized` | 동시에 1개 | 낮음 | 편리한 사용, 메소드/블록/클래스/객체 별 Lock 제어 가능, JVM 최적화로 경합이 적은 시나리오에서 우수한 성능 가능성 |
| `ReentrantLock` | 동시에 1개 (유연한 적용 가능) | `synchronized`보다 높음 | `synchronized`에 비해 **유연하고 다양한 기능** 제공 (`tryLock`, `timeout`, `fair` 기능 등)으로 복잡한 상황의 동시성 제어에 유리 |
| `Semaphore` | **N개**까지 접근 허용 | `synchronized`보다 높음 | 지정된 수만큼의 스레드가 동시에 접근하도록 제어 |
| `ReadWriteLock` | 읽기 작업에 대한 **높은 동시성** | 가장 높음 | 읽기 작업 간에는 동시 접근 허용, 쓰기 작업 시에만 배타적 접근 보장 |

* **성능:** 명시적으로는 `ReentrantLock`이 `synchronized`에 비해 나은 성능을 보인다고 알려져 있었으나, 최근에는 경합이 적은 시나리오에 대한 JVM 최적화로 **`synchronized`가 나은 성능**을 보이는 경우도 있습니다.

---

## 동시성 이슈 재현을 위한 도구 비교

동시성 이슈 재현 시나리오에서 스레드 동기화를 위한 도구 비교:

| 도구 | 목적 | 사용사례 |
| :--- | :--- | :--- |
| **`CountDownLatch` / `CompletableFuture`** | N개 스레드들의 작업이 **모두 완료된 시점**을 알 수 있음 | 작업 완료 후 결과 집계에 용이 |
| **`CyclicBarrier`** | 모든 스레드가 **동시에 시작**하도록 할 수 있음 | 스레드들의 동시 시작점에 초점을 맞출 때 용이 |

* **판단:** 충분히 큰 작업을 진행한다고 하면 동시성 이슈 재현에는 두 방법(작업 완료 확인 vs 동시 시작) 모두 적합하다고 판단됩니다.
* **실제 영향 요소:** 오히려 위 도구들보다는 **스레드 개수**와 **작업의 크기**가 동시성 이슈 재현에 더 큰 영향을 미칩니다.
* **테스트 코드 선택:** 구현이 용이하고 N개 테스트 진행 완료 시점에 데이터를 모아볼 수 있는 **`CompletableFuture`**를 이용해 테스트 코드를 작성했습니다.

## 동시성 이슈 재현 테스트 결과

**테스트 조건:** 총 포인트 충전 횟수를 100, 200, 500, 1000회로 증가시키면서 스레드 개수를 변화시키며 테스트 진행 (MAC OS 8코어(성능4 + 효율4) 환경)

**결론:** 스레드 개수가 증가할수록, 총 수행횟수가 증가할수록 **동시성 이슈 재현확률이 증가**합니다. 그럼에도 항상 재현되지는 않습니다. **재현확률을 증가시키려면 필연적으로 테스트 수행시간이 증가할 수밖에 없습니다.**

### `synchronized` 적용 시 수행시간 (참고)

* 1000회 (스레드 32개) 수행에 **407초** 소요
* 200회 (스레드 8개) 수행에 **81초** 소요

### 최종 결론 및 테스트 전략

* 높은 확률로 동시성을 재현하기 위해서는 **많은 작업을 동시에 수행**해야 하며, 이는 **테스트 실행시간 증가**로 이어집니다.
* 따라서 위와 같이 오래 걸리는 테스트 케이스는 **테스트 파이프라인에서 분리하여 별도 실행**하는 것이 필요합니다.
